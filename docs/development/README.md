# 开发状态与交接记录

本目录保存跨任务的开发状态、下一步路线和已完成任务的交接记录。Git 提交说明代码改动；开发记录补充需求背景、实现选择、参与者、验证证据和遗留事项。记录不能替代源码、ADR、API 契约或测试结果。

## 文件职责

- [当前状态](current-status.md)：当前分支基线、已落地事项、待核实/验收事项。
- [路线图](roadmap.md)：阶段顺序、依赖及退出条件；变更时说明原因。
- `logs/YYYY/DEV-NNN-*.md`：一项完整任务的过程与交接记录，按年份和递增编号归档。
- [任务日志模板](task-log-template.md)：复制后填写；不适用项明确写“无”，未运行项写“未运行”及原因。

## 记录规则

1. 每项完整功能或跨模块工程任务完成时新增一份日志；小型独立修复可以在现有任务记录中追加。
2. 开始任务时记录基线分支和 SHA、任务协调人、参与者、交叉审查者及修改等级；人员未确定时标注待填写，不猜测姓名或审查结果。
   三人并行开发还须先约定垂直切片、负责人/文件归属、接口依赖和集成负责人，具体见 [协作指南](../../CONTRIBUTING.md#三人并行任务拆分)。
3. 记录实际变更的前端、后端、配置、文档和脚本路径；明确是否改变数据库、API、正文/来源契约及兼容行为。
4. 只记录真实执行的命令、环境、退出码和结果；区分自动化检查、人工浏览器验收、真实资料/模型验证。未运行或失败的检查不得写成通过。
5. 记录最终分支、提交 SHA、PR 链接（若有）、遗留问题、风险和建议后续任务。未提交时明确写“未提交”。
6. 不在日志中复制密钥、真实课件、真实会话正文、用户数据库内容或其他敏感数据。

## 状态用语

- **已实现**：代码或文档已存在；不自动表示已经通过验证。
- **已验证**：列出可复现的实际检查及结果。
- **待验收**：仍缺全量自动回归、人工流程、真实材料或外部服务证据。
- **Proposed**：架构方案待审；未获接受前不是已批准的长期决策。
- **阻塞**：列出具体依赖、负责人/所需输入及恢复条件。
