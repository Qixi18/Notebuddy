# 工程与产品路线图

按实际代码能力和未验证风险排序；已存在的模块以稳定性与验收为目标，不重复列为从零开发。状态依据见 [当前开发状态](current-status.md) 与 [验收快照](../acceptance.md)。

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 工程稳定性 | 让完整 CI 在目标分支实际运行；修复前后端回归；验证 Notebook 正文保存、PDF/图片处理及 Generation Worker 并发安全 | 记录对应提交的完整自动结果；关键保存/解析/任务失败路径经隔离测试和浏览器或真实资料验收 |
| P0 协作门禁 | 审查 CI 触发分支并由管理员核实固定分支保护与实际 required check | 工作流与协作规范一致；远端配置经管理员界面核实，不能仅凭文档宣称生效 |
| P1 核心业务完善 | 改善 Notebook 编辑体验、AI 答疑证据质量、森林关联定位、文件质量门禁与跨模块接口稳定性 | 按垂直用例明确缺陷、契约和验收证据；真实模型及资料验证另列结果 |
| P1 架构审查 | 审阅 ADR-0001 至 ADR-0004 的实施证据及剩余例外 | 技术把关者决定接受、修订或继续 Proposed；不机械拆分简单 Router |
| P2 工程扩展 | 扩展 Agent 工具与检索质量、移动端 API 适配、性能和可观测性、必要的自动化覆盖 | 每项先界定用户价值、接口与数据边界，再确定实现和测试范围 |

每项工作由负责人指定业务切片、文件归属、接口依赖和验收条件；按 [协作指南](../../CONTRIBUTING.md) 集成。路线图不代替当前测试报告。
