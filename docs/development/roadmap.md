## 接续事项

1. 在 GitHub Actions 查看 CI 的依赖安装、架构检查和完整回归实际结果；修复失败并在日志中记录真实结论。
2. 由仓库管理员核对 `main` 与 `feat/debug-integration` 的分支保护，并仅在 CI 已有稳定检查名称后设为 required；此远端操作不由本地 workflow 自动完成。
3. 对本次资料和 Notebook service 抽取执行针对性回归，确认 HTTP 状态/响应体/事务语义保持；再选下一垂直领域，不做大范围机械迁移。
4. 随垂直业务用例增加架构检查规则，逐步收敛旧路由/Service 边界；新规则应先验证当前基线，避免无意中把历史违规伪装成合规。
5. 继续跟踪 ADR-0001/0002、完整回归、浏览器人工验收和真实资料/模型验收，不把文档或静态门禁视为业务验收。
