# NoteBuddy 界面设计系统规划

> 基于当前代码实测得出的规划文档。文中所有对比度均为 WCAG 2.2 公式实算值，非估算。
> 配套可落地文件：`docs/design/tokens-proposed.css`（候选 token，未接入生产）。

---

## 0. 现状诊断

在写方案前先量了现状。六个问题，按影响排序：

| # | 问题 | 实测证据 | 影响面 |
|---|---|---|---|
| **D1** | **三个字体 token 塌成同一个栈** | `course-assistant.css:12-14` 把 `--nb-serif`/`--nb-sans`/`--nb-mono` 全改成 `Inter, "Microsoft YaHei", …`；而 Inter **根本没加载**（无 `@font-face`、无外链、系统未安装）→ 实际全落到雅黑 | 全站。衬线/等宽的设计意图完全失效，层级只剩字号 |
| **D2** | **字号 45 档** | 8–11px 共 669 处使用；8/9/10/11/12/12.5/13/13.5/14/14.5… 全部并存 | 全站。层级噪声，无法形成稳定刻度 |
| **D3** | **非文字轮廓全线不达标** | `--nb-line #e5e7e2` on 白 = **1.25:1**（SC 1.4.11 需 ≥3:1）。**1px 改 2px 后仍是 1.25:1** —— 加粗只增加视觉重量，不增加对比度 | 全站所有卡片与分隔线 |
| **D4** | **小字严重不达标** | 会话计数 `#a3ada3` 9.5px on 绿底 = **1.95:1**（需 4.5:1） | 左栏 |
| **D5** | 次要文字差 0.07 | `--nb-muted #6f7b6f` on 白 = **4.43:1**，阈值 4.5 | 全站 |
| **D6** | **断点体系分裂** | `course-assistant.css` 用 1439/1120/900/600；`styles.css` 用 1100/920/760/560/480/460；`redesign.css` 用 1120/900/600 —— 全项目 **12+ 个不同断点** | 全站 |

**结论**：当前不是"风格没定"，而是**风格被实现细节吃掉了**。原始设定是 `redesign.css` 头部注释写的 *White Field Notes*（白田笔记）：白纸、墨绿、宋体、细线。这套语言本身是对的，问题在于 token 被覆盖、字号没有收敛、对比度没人验。

## 1. 设计基础

**风格定位**：白田笔记 —— 白纸为底、墨绿为墨、宋体为标题、等宽为注。**克制、可信、有批注感**。这是学术工具该有的气质：不炫技，但每处细节经得起看。

四条不可让步的原则：

1. **纸感优先** —— 界面是"纸"，内容浮在纸上。任何装饰性底色（如左栏绿）只能作为"装订区"级别的暗示，不能抢正文的注意力。
2. **层级靠排版，不靠描边** —— 标题层级由字号 + 字重 + 留白承担，描边只用于分区，不用于制造层级。（当前 45 档字号正是这条没落实的产物）
3. **动效只解释因果** —— 只动 `transform` / `opacity`，时长 120–240ms。超过 400ms 的动画会让长文阅读变成负担。
4. **不靠颜色单独传意** —— 选中态、错误态、依据编号都要有第二通道（图标/文字/形状/位置）。

## 2. 色彩系统

### 2.1 现状实测

| 用途 | 现状 | 对白底对比度 | 判定 |
|---|---|---|---|
| 正文 `--nb-ink #1f2a22` | 14.5px | **14.87:1** | ✅ AA |
| 次要文字 `--nb-muted #6f7b6f` | 11–12px | **4.43:1** | ⚠️ 差 0.07 |
| 会话计数 `#a3ada3` | 9.5px on 绿底 | **1.95:1** | ❌ 差 2.5 倍 |
| `--nb-sage #8fa98c` | 标签/描边 | 2.55:1 | ⚠️ 仅装饰可用 |
| 卡片轮廓 `--nb-line #e5e7e2` | 1px / 2px | **1.25:1** | ❌ 组件边界需 3:1 |
| 左栏分隔线 `#dbe3d7` | 2px on 绿底 | **1.11:1** | ❌ |
| 左栏底 `#e6eee0` vs 中栏白 | — | 1.19:1 | ⚠️ 装饰性表面差 |
| 主色 `--nb-forest #2f5d45` | 按钮/链接 | **7.57:1** | ✅ AAA |

**关键澄清（避免过度整改）**：SC 1.4.11 要求 ≥3:1 的是"**识别 UI 组件与状态所必需**的视觉信息"。所以：

- **分栏线、卡片分隔线**属装饰性布局，**不强制** 3:1 —— 当前 1.25:1 不是违规。
- **输入框、按钮、可点击卡片的边界**属组件边界，**必须** ≥3:1 —— 当前不达标，这是要修的。
- **你刚把内部线加粗到 2px**：增加了视觉重量，但对**对比度零贡献**（1.25:1 → 1.25:1）。重量与对比度是两件事，视觉上"更明显"并不等于"更可辨"。

| `--nb-ink-subtle` | `#8a948a` | 3.20:1 | 纯装饰文字 / 大字号 |

## 3. 字体与排版

### 3.1 字体族：先把三族拆开

现状问题（`course-assistant.css:12-14`）：

```css
--nb-serif: Inter, "Microsoft YaHei", "PingFang SC", system-ui, sans-serif;
--nb-sans:  Inter, "Microsoft YaHei", "PingFang SC", system-ui, sans-serif;
--nb-mono:  Inter, "Microsoft YaHei", "PingFang SC", system-ui, sans-serif;  /* 连等宽都不是 */
```

且 **Inter 从未被加载**（无 `@font-face`、无 Google Fonts 外链、Windows 字体目录也没有）。实际渲染落到雅黑 —— Windows 下数字与拉丁字母都是雅黑字形，**引用角标「①②」和代码片段的等宽对齐全部失效**。

**建议**：

| 角色 | 字体 | 落地方式 |
|---|---|---|
| 正文 | Inter var + Source Han Sans SC / 思源黑体 | **自托管 woff2**（`public/fonts/`），`font-display: swap` |
| 标题 | Noto Serif SC / 思源宋体 | 自托管，仅打包 SC 子集（regular 400 + semibold 600） |
| 等宽 | JetBrains Mono | 自托管，**仅用于编号与代码**（角标、页码、diff） |

**成本提示**：思源宋体全字重中文 woff2 约 8–10MB。务实做法：**只给标题用宋体，字符子集按需**（课程标题、问答标题这类），或者标题也走黑体 600 —— 视觉损失小，体积损失大。**建议先做"标题黑体 600 + 正文黑体 400"的两档分离，把等宽先修好**（角标对齐是当前看得见的瑕疵）。

### 3.2 字号刻度：45 档 → 7 档

| Token | 值 | 用途 | 替代现状 |
|---|---|---|---|
| `--nb-fs-12` | 12px | 辅助文字、时间戳、表格 | 8/8.5/9/9.5/10/10.5/11/11.5 |
| `--nb-fs-13` | 13px | 次级控件、会话标题 | 12.5/13 |
| `--nb-fs-14` | 14px | 正文基准、列表 | 13.5/14 |
| `--nb-fs-16` | 16px | **回答正文**、卡片标题 | 14.5/15/16/17 |
| `--nb-fs-20` | 20px | 区块标题 | 18/19/20/21 |
| `--nb-fs-24` | 24px | 页面标题 | 22/23/24/25 |
| `--nb-fs-32` | 32px | 空态 / 展示数字 | 26–48 |

**规则**：新代码只允许用这 7 档；现存 8–11px 的 669 处中，**辅助文字统一提到 12px**（也是 D4 的修复：9.5px 计数在绿底上只有 1.95:1，提到 12px 并换 `--nb-ink-muted` 即达标）。

### 3.3 行高与字重

| Token | 值 | 场景 |
|---|---|---|
| `--nb-lh-tight` | 1.35 | 标题（20px 以上） |
| `--nb-lh-snug` | 1.5 | 按钮、chip、输入框 |
| `--nb-lh-normal` | 1.65 | 界面正文（现状 1.65 ✅） |
| `--nb-lh-prose` | 1.9 | **长文阅读**（回答正文，现状 1.9 ✅ 保留） |

字重只用四档：`400 / 500 / 600 / 700`。**中文避免 300 以下**（雅黑 Light 在小字下发虚）。

## 4. 移动优先布局

### 4.1 统一断点

现状 12+ 个断点必须收敛。建议全项目统一为 6 档：

| 断点 | 名称 | 布局行为 |
|---|---|---|
| **≥ 320px** | XS | 单列；左栏走抽屉；卡片去边框通栏 |
| **≥ 576px** | SM | 单列 + 更大留白；输入框与内容同宽上限 640px |
| **≥ 768px** | MD | 单列 + 顶部工具条；**左栏仍为抽屉**（平板横屏也不并排，避免挤压阅读列） |
| **≥ 992px** | LG | **两栏**：左栏常驻 216px + 中栏；右栏仍为抽屉 |
| **≥ 1200px** | XL | 三栏：左栏 240px + 中栏自适应 + 右栏 264px |
| **≥ 1440px** | 2XL | 三栏加宽，左栏 252px / 右栏 280px（现状） |

### 4.2 三栏在各断点的行为

| 断点 | 左栏（桌宠+会话） | 中栏（对话） | 右栏（改动） |
|---|---|---|---|
| XS–MD | 抽屉（顶部「会话」按钮唤起，带遮罩） | 全宽 | 抽屉 |
| LG | 常驻 216px | 自适应 | 抽屉 |
| XL+ | 常驻 240–252px | 自适应 | 常驻 264–280px |

**移动优先的正确写法**：先写单列基础样式，再用 `@media (min-width: …)` 逐级增强。
现状是**先写三栏桌面样式、再用 `max-width` 降级** —— 这导致每个断点都要覆盖上一版，规则越堆越乱（`course-assistant.css` 里已有 4 个重叠的媒体查询组）。

### 4.3 栅格与间距

- **8px 基线**：`--nb-space-1…12` = 4/8/12/16/20/24/32/40/48
- 页面左右安全边距：XS 16px → SM 24px → MD 32px → XL 40px
- 卡片内边距：12/16（紧凑）→ 20/24（宽松）
- **触控目标 ≥ 44×44px**（WCAG 2.5.8）—— 仅 `pointer: coarse` 生效，桌面不损失密度
- 内容行长：回答正文建议 **≤ 72 个中文字符**；超宽屏时中栏不无限拉伸，靠 `--nb-forest-*` 留白收边

### 4.4 窄屏必查项

- 输入框固定在底部时需 `env(safe-area-inset-bottom)`
- 抽屉打开时锁定背景滚动 + 焦点移入抽屉、Esc 关闭
- 长会话标题在窄屏走 `text-overflow: ellipsis`（当前 hover 跑马灯是桌面增强，窄屏不需要）

## 6. 微交互参数

| 场景 | 属性 | 时长 | 缓动 |
|---|---|---|---|
| 按钮/链接 hover 底色 | `background-color` | 120ms | `ease-out` |
| 卡片按下 | `transform: scale(0.98)` | 200ms | `ease-out` |
| 抽屉滑出 | `transform: translateX()` | 320ms | `ease-in-out` |
| 长标题跑马灯 | `transform` | 2.4–7s（按距离） | `linear` |
| 消息淡入 | `opacity` + `translateY(4px)` | 200ms | `ease-out` |
| 角标定位滚动 | `scroll-behavior` | 320ms | `ease-in-out` |

**只允许动 `transform` / `opacity`**（GPU 合成，不触发重排）。`scroll-behavior` 与 `scrollBy` 例外可用，但**不要对页面根容器用 `scrollIntoView`** —— 会把整页拽动，移动端尤其明显（当前实现已规避，见 `SourcesRow`）。

`prefers-reduced-motion: reduce` 下全部降为 0.01ms（现状已覆盖，需补 `scroll-behavior: auto`）。
