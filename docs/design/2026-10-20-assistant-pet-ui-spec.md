# 答疑桌宠 · 界面设计规范 v3（简化版 · 同色深绿）

- 日期：2026-10-20（rev.7 历史按作用域）
- 参照：课程页视觉方案（浅底 + 白色大卡 + 深绿主色 + 宋体标题 + 细描边）
- 产物：`docs/design/assistant-pet-ui-v3.html`（交互稿）、`docs/design/assistant-pet-ui-v3.png`（1440 × 920）
- 范围：只覆盖答疑桌宠页；不改动其他页面与后端

## 一、设计原则

**一句话：一屏只留三类东西——桌宠、对话、依据。**

rev.3 做了三件事：**去深绿卡、全站去渐变、把绿色从"一块深色"改成"一层浅色"**。
绿色不再靠一张深色卡片压场，而是分布在标题、分区标签、依据卡底色、气泡、药丸与描边上——面积更大，但每一处都轻。

| 删掉 | 原因 |
|---|---|
| 顶部搜索行 | 会话搜索放进会话列表更自然，页面首屏不需要两个入口 |
| 标题分隔线 + 右侧资料计数 | 一条细线切断了呼吸感，计数对提问没有帮助 |
| 左栏「当前课程」卡 + 底部范围/目标 | 与中栏 chips 重复，课程名并进标题 |
| 依据栏分组标签（课程/网络） | 靠卡片上的标签就能区分，少一层缩进 |
| 输入框内的 @资料/#页面 chips | 上下文已在顶部常驻，输入框只负责打字 |
| 依据栏底部图例 | 标签自带「支撑/部分支撑」文字，不需要再解释一遍 |

**字号整体上调一级**：正文 13 → **14.5**，会话 12 → **13.5**，依据标题 11 → **13**，页标题 25 → **26**。

**不用的手法**：渐变（背景、按钮、光晕一律纯色）、深色大卡、彩色语义标签。

## 八、无障碍

- **键盘**：Tab 顺序 = 侧栏 → 新对话 → 会话 → 上下文 → 正文角标 → 依据卡 → 输入 → 发送。
- **焦点环**：`2px solid var(--g500)` + `offset 2px`，不隐藏。
- **语义**：对话 `role="log" aria-live="polite"`；角标 `aria-label="第 1 条依据，第 3 讲第 18 页"`；桌宠 `role="img"`。
- **触控**：移动端把 chip/按钮热区补到 44×44（视觉尺寸不变）。
- **动效**：`prefers-reduced-motion` 下取消惯性、上浮与呼吸。
- **缩放**：200% 时触发单列断点，不出现横向滚动。

## 十一、rev.4：卡片系统

上一版（rev.3）的问题是**卡片语言不统一**：只有依据栏是卡，回答区是纯文字，输入框是另一张卡，桌宠既不是卡也不是列表。于是"卡片风格"只落在了右栏。

rev.4 定了一条规则：**一页三种卡，同一套几何，按角色分配底色。**

| 卡 | 角色 | 底色 | padding | 说明 |
|---|---|---|---|---|
| 回答卡 | 阅读 | `#FFFFFF` | 16 / 18 | 唯一的"主卡"，头部放头像与时间，动作条在卡内底部 |
| 依据卡 | 参考 | `#F6FAF7` | 12 / 13 | 略小、略浅，选中转白 + 深绿描边 |
| 输入卡 | 操作 | `#FFFFFF` | 12 / 14 | 与回答卡同色，焦点时描边转绿 |

**统一项**：圆角 12、1px 描边、无阴影（选中态除外）、卡间距 8–14。
**引文**不再单独铺一层浅绿，改成左侧 2px 规线——同一张卡里最多只有一层色。
**分隔线**只保留侧栏那一条；桌宠区、动作条、标题行的线全部去掉，用间距分隔。

**为什么这样更"极简"**：线少了、色块少了、但层级更清楚——三张卡的位置就说明了它们的关系（读 / 查 / 写），不需要再靠标签或分割线解释。

**层级修正**：rev.3 右栏三张卡比中间正文更"重"，视线先落在依据上；rev.4 把回答变成有描边的主卡、依据卡降为浅底，视线回到正文。回答小标题从 15px 提到 16.5px，与 14.5px 正文拉开一级。

## 十二、rev.5：取消右栏，依据回到卡里

**为什么还是偏右**：rev.4 把回答做成了主卡，但右栏三张卡依然是一块**独立的、有边界的矩形色块**——它占着页面 304px 的宽度、从上到下都有内容，视觉重量天然大于中间那张白卡。只要它常驻，页面就会右倾。

**改法不是调轻右栏，而是取消右栏。**

| 原来 | 现在 |
|---|---|
| 右栏 304 常驻，三张依据卡 | 依据收进回答卡底部，一行 chips |
| 上下文条只有范围/目标 | 右侧放「＋新对话」，右上角不再有孤立按钮 |
| 内容区 1176 通栏 | 左栏 + 阅读列组成 1000 的块，整体居中 |

**关键数字**：内容区 1176 → 居中块 1000（左右各 88）→ 左栏 240 + 间距 24 + 阅读列 736。阅读列 736 减去卡片内边距 36，正文宽 700，每行约 48 个汉字。

**依据行**：`依据 3 段` + 三个 chip（序号、讲次、页码、支撑点）+ 右侧「查看原文 →」。点角标高亮对应 chip，点「查看原文」再展开完整摘录。既保住了"可核验"，又不占一整栏。

**收益**：
1. 页面只剩一条竖直阅读动线，视线从左到右的跳跃消失了；
2. 回答卡成为唯一的"主卡"，层级不再被右栏抢；
3. 宽度从 1176 收到 1000，留白变成左右对称的页边，而不是右侧一块空地。

## 十三、rev.6：右侧改动栏

**为什么右栏又回来了**：这次不是"依据"，而是**本次会话改过的笔记**。它和依据的区别在于——依据是"读"，改动的笔记是"写"，需要用户确认，属于任务状态，应该常驻可见。

**为什么不会再次右倾**：

| 上一版右栏（依据卡） | 这一版改动栏 |
|---|---|
| 304 宽，3 张有边界的卡 | 280 宽，**无卡片边框的列表**，只有行分隔线 |
| 常驻不可收 | 可收成 44px 竖条 |
| 与正文抢注意力 | 颜色只在 `+/−` 和预览的增删行上，其余是文字 |

**结构（参考 Zcode 的「未暂存」列表）**

```
本次改动 3                        ↻  ›
─────────────────────────────────
◧ 红黑树的五个不变量      +12 −4
  第 3 章 · 树
  ┌ 预览 · 第 3 节        待确认 ┐
  │ − 五条不变量：节点非红即黑…  │
  │ + 四条性质：节点非红即黑…    │
  │   插入只会破坏第 4 条       │
  │ 打开笔记 →                  │
  └────────────────────────────┘
◧ AVL 与红黑树对比         +6 −1
◧ 树的遍历笔记              +3
─────────────────────────────────
[        全部写入笔记        ]
```

**交互**
- 点行：选中并在行下展开预览（手风琴，一次只开一条）。
- 点「打开笔记」：跳到该笔记并定位到变更小节。
- 「全部写入笔记」：批量确认本次会话的建议，等价于逐条采纳。
- 收起：右上角 `›` → 44px 竖条；点竖条里的 `‹` 恢复。

**数据来源（实现前要确认）**
- 现有 `api.listSuggestions(noteId)` 是**按笔记**查；改动栏需要**按会话聚合**。
- 短期：从 `conversation.agentRun.final.suggestions` 里筛 `note_edit` 累计。
- 长期：加 `GET /conversations/{id}/changes`，返回 `[{note_id, note_title, chapter, added, removed, status}]`。
- 只有 agent 链路（`propose_note_edits`）会产生这类数据；页面当前用 `ask`，所以本阶段的改动栏是**空态或隐藏**，等 S4 接入后才出现内容。

**空态**：没有改动时，整栏收起为 44px，竖排显示「改动 0」，不占阅读宽度。

## 十四、rev.7：历史记录按「课程 → 作用域」两级

**为什么不用时间**：时间分组回答的是"什么时候问的"，用户找历史时想的是"我在哪儿问的"。同一门课的会话被拆到今天/昨天/更早三段，反而要逐段翻。

**结构**

```
全局可查                        ← 一级：跨课程（无子组）
  跨课程对比红黑树与 AVL
  图算法出现在哪些课程

▾ 数据结构  6 段会话            ← 一级：课程（可折叠）
    整门课程  3                 ← 二级：范围（缩进 14）
      红黑树的旋转规则
      B+ 树与磁盘 IO
      最短路径复习
    📄 红黑树的五个不变量  2     ← 二级：笔记（缩进 14，带文档图标）
        黑高定义是不是写错了     ← 三级：会话（再缩进 20）
        这节的四条性质
    📄 树的遍历  1  ▸           ← 折叠的笔记子组

▸ 计算机网络  2 段会话          ← 折叠的课程
```

- 一级：全局可查 + 各门课程，可折叠。
- 二级：「整门课程」与每篇笔记，缩进 14px；笔记带文档图标，标题比会话重一级（12px / 600）。
- 三级：会话行；课程级缩进 14，笔记级再缩进 20，形成"笔记比课程深一格"。
- 计数：课程头显示总条数，二级头显示该组条数。

**为什么笔记放在课程内部，而不是单开顶级「笔记」组**

1. 归属清楚：笔记属于课程，历史跟着对象走，不制造第三根轴；
2. 回忆线索：笔记名比"哪门课"更具体，作为二级标题最醒目；
3. 不拆散：单开顶级组会把一门课的会话分到两个地方，找的时候要来回跳；
4. 备选「完全隐藏，只在笔记页看」被否掉——从答疑页就再也找不到那条会话。

> 同一条笔记会话在「笔记页的悬浮坞」里也能看到：同一份数据，两个入口，不复制。

**排序**：全局固定第一；课程按最后活动倒序；课程内「整门课程」在前，笔记按活动倒序跟随；组内按最后活动倒序，时间只作行尾信息。

**归属怎么定（数据前提）**

- 会话需要记住 `scope`（course/global/note）+ `note_id` + 笔记标题快照。
- 现状：`Conversation.default_scope` 恒为 `course`，提问时的范围只是坞里的局部 state，**没有落库**。
- 建议：**首次提问时把当时的范围写成会话归属**；之后同一会话内改范围不搬家（否则列表会跳），只在对话头部显示"当前范围"。
- 后端：`conversations` 增加 `scope`、`note_id`、`note_title`。

**交互**

- 一级与二级都可折叠，折叠状态写 `localStorage`；当前会话所在的两级默认展开。
- 空组不渲染；没有会话时显示「还没有会话」。
- 「全部 →」进入完整历史页，层级规则相同。
