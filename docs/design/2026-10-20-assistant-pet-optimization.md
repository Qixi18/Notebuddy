## 一、结论摘要

1. **信息架构要换，不是换皮。** 现状把桌宠、课程、会话、设置、术语五类内容塞进 300px 左栏（`AssistantPage.tsx:150-248`），而真正需要并排看的「回答 + 依据」却一个在正文底部折叠、一个点开就跳走。
2. **建议改为三区工作台**：左栏 252px（桌宠 + 会话历史）／中栏自适应（对话主线）／右栏 320px（依据台，可收起）。依据从「折叠面板」升级为「常驻侧栏」，点角标就地定位，不离开对话。
3. **功能按三档推进**：P0 先修信息架构（会话列表、上下文可见、角标引用、依据台、执行步骤），P1 补学习闭环（追问建议、术语就地解释、反馈原因、写入笔记）与**可拖动的桌宠浮层**，P2 做事件感知与快捷键。
4. **不要重造轮子。** 悬浮坞 `AssistantDock.tsx` 已经解决了会话共享、来源卡片、写入笔记、建议卡、宽度拖拽；答疑页缺的主要是「布局」和「把 agent 能力接回来」。

## 三、同类产品调研

### 3.1 学习答疑类

| 产品 | 核心机制 | 值得借鉴 | 不适合照搬 |
|---|---|---|---|
| **Khanmigo**（可汗学院） | 苏格拉底式提问，拒绝直接给答案，反问「你先试了什么」；绑定课程练习与视频 | 把「学习目标」变成影响回答策略的真实参数，而不是装饰性下拉 | 强引导对赶作业的用户过于啰嗦，需要「直答/引导」档位 |
| **Photomath** | 拍照 → 分步解法，步骤本身就是内容；AR 叠加 | 步骤要可读、可停在任意一步 | 只做数学，且没有资料溯源 |
| **Socratic → Google Lens** | 多学科拍题，关联 YouTube 讲解 | 低成本的多模态入口 | 纯检索型，不追问、不追踪掌握度 |
| **豆包爱学** | 对话式启发、多轮追问、动态讲解、不直接给答案；「答疑—批改—巩固—陪伴」闭环 | 陪伴感来自「连续追问」而不是卖萌 | 闭环依赖题库，本项目应以课程资料为边界 |
| **小猿 AI / 快对 AI** | 拍照搜题、分步解析、错因定位、错题本 | 回答末尾给「下一步动作」（练习/错题），而不是结束即终点 | 题库型产品，与资料型问答不同 |

### 3.2 资料型问答（与本项目最接近）

| 产品 | 核心机制 | 值得借鉴 |
|---|---|---|
| **NotebookLM** | 回答每个结论附**数字角标**；悬停预览原文、点击打开来源面板并高亮对应段落；来源可勾选缩小范围；资料里没有就明说「不在来源中」 | ①角标 + 依据面板是「低幻觉感」的来源；②范围必须常驻可见；③拒答要显式 |

NotebookLM 的做法说明了一件事：**可核验性不是靠一句「回答附来源」，而是靠「角标在句子上、原文在隔壁」**。当前实现把来源放在消息底部并折叠，恰好把最强的信任机制藏了起来。

### 3.3 桌宠 / 伴随型

| 产品 / 方案 | 核心机制 | 值得借鉴 |
|---|---|---|
| **Shimeji 类桌宠** | 点击不同部位触发不同反应；用位移阈值（约 4–5px）区分「点击」与「拖拽」；台词气泡跟随主体移动 | 桌宠要有「被摸到就有反应」的即时反馈 |
| **whale-pet / whalepal** | 状态机 idle / walk / work / sleep / drag / react；**读取 Agent 会话事件**切换动作（编码、思考、等待审批、报错）；优先级仲裁 + 去抖；拖动挤压、惯性、贴边；支持 `prefers-reduced-motion` | ①桌宠状态应绑定「AI 正在做什么」，随机卖萌是噪音；②高频状态切换要防抖；③动效必须可关闭 |

当前 `TeacherCharacter` 已有 idle / thinking / explaining / error 四态与四张立绘（`TeacherCharacter.tsx:16-21`），**能力已经在，缺的是把状态接到真实事件、以及让桌宠可交互**。

### 3.4 五条设计原则（本方案的依据）

1. **依据在阅读动线上**：角标在句子上，原文在隔壁（NotebookLM）。
2. **范围一直可见**：用户随时知道「这轮答案基于什么」（NotebookLM 的来源勾选）。
3. **桌宠状态要有意义**：绑定检索/写作/出错/等待，而不是随机动画（whale-pet）。
4. **一轮问答要有下一步**：追问、练习、记笔记，形成闭环（豆包爱学 / 小猿）。
5. **一屏只做一件事**：问 → 读 → 核，三件事按列分区，不互相挤占。

### 4.1 三区结构

```
┌─ 236 全局导航 ─┬─ 顶栏 60px：课程路径 / 会话搜索 / 新对话 ─────────────────────────┐
│                ├──────────────┬──────────────────────────────┬───────────────────┤
│                │ 左栏 252px   │ 对话主线（自适应，行宽≈600） │ 依据台 320px      │
│                │              │                              │                   │
│                │ 桌宠舞台     │ 上下文条（范围/目标，可改）   │ 回答依据 3        │
│                │ 身份/状态    │ ─────────────────────────    │ · 课程资料 2      │
│                │ 当前课程卡   │ 消息流                       │   片段高亮/页码    │
│                │ ──────────   │  · 用户提问（右对齐气泡）     │ · 网络补充 1      │
│                │ 会话历史     │  · 回答 + 角标 + 行动条       │ · 术语 1          │
│                │ 今天/昨天    │  · 追问建议 chips             │ （相关笔记可选）   │
│                │ 更早         │  · 执行步骤 + 流式           │ 证据强度说明      │
│                │ ──────────   │ ─────────────────────────    │ （可收起）        │
│                │ 范围/目标摘要 │ 输入区（@资料 / #页面 / 目标）│                   │
└────────────────┴──────────────┴──────────────────────────────┴───────────────────┘
```

### 4.2 尺寸与断点

| 断点 | 布局策略 |
|---|---|
| ≥ 1440 | 导航 236 + 左栏 252 + 中栏自适应 + 依据台 320（默认展开） |
| 1120 – 1440 | 依据台默认收起，点角标从右侧滑出抽屉（覆盖中栏，不挤压） |
| 900 – 1120 | 左栏压到 216；依据台与会话列表都用抽屉 |
| < 900 | 单列：顶部 52px 桌宠条（头像 + 课程 + 状态）、会话抽屉、输入区 sticky 贴底 + 安全区 |

### 4.3 各区域内容

**顶栏（60px）**
- 左：课程 / 答疑桌宠 / 会话标题（面包屑）
- 右：搜索会话（Ctrl+K）、依据栏开关、＋新对话、头像
- 移除页内 42px 大标题，标题语义交给面包屑与首条消息

**左栏（252px）**
- 桌宠舞台：立绘 + 地面涟漪 + 一句话气泡（随上下文变化）
- 身份：姓名 / 角色 / 状态胶囊（思考中可打断）
- 当前课程卡：课程名 + 资料/笔记数 + 概览入口
- 会话历史：今天 / 昨天 / 更早，标题 + 时间；hover 出现更多操作
- 底部：范围与目标摘要（点击直达修改）

**对话主线（自适应）**
- 上下文条：范围 chips + 目标 chip + 检索结果计数
- 消息流：用户气泡右对齐；回答左对齐并带角标、行动条、追问建议
- 执行步骤：检索/阅读/查找以时间线展示，可折叠
- 输入区：@资料、#页面、目标标签；Enter 发送、Shift+Enter 换行、可停止

**依据台（320px）**
- 分组：课程资料 / 网络补充，课程与网络分开标注；术语在回答内悬停出现（虚线标记），不占侧栏；相关笔记作为可选分组按需出现
- 每张来源卡：序号、课件名、页码、命中片段（高亮）、支撑等级、打开课件
- 点击角标 → 对应卡片高亮并滚动到位；点击「打开课件」新开页或侧栏预览，不打断对话
- 底部：证据强度图例（支撑 / 部分支撑 / 推断）

### 4.4 桌宠的位置模型（三档，可自由拖动）

| 档位 | 形态 | 触发 | 说明 |
|---|---|---|---|
| A · 栏内 | 左栏立绘 | 默认 | 随问答切换四态；点击说一句上下文提示；拖出即进入 B |
| B · 浮层 | 自由浮动立绘（120px） | 从 A 拖出 / 双击桌面空白 / 页头开关 | 可在视口内任意拖动，超 6px 才算拖拽；松手有惯性；贴边吸附半隐藏；位置记忆 |
| C · 球 | 56px 悬浮球 | 拖到角落 / 点收起 | 复用现有 `AssistantDock` 的开合与宽度记忆；点击展开抽屉 |
| 窄屏 | 顶部 44px 头像条 | < 900px | 不浮层，避免遮挡；点击展开全屏对话 |

**拖出之后左栏怎么办（不留空槽）**

- 舞台那 216px **不是固定占位**，而是随形态收起：拖出后整块消失，不是留一块空白。
- 身份区从 70px 压成 **44px 锚点行**：小头像 +「莉艾尔」+「在页面上 · 正在读第 4 讲」+「召回 ←」。它不可拖拽、不弹气泡，只回答两个问题：它去哪了、怎么叫回来。
- 会话列表 `flex: 1` 自然上移，吃掉约 240px；实拍见 `assistant-pet-float.png`。
- 拖回时，左栏顶部出现 216px 虚线投放区（仅拖拽中出现）；拖到左栏边缘 56px 内也判定归位，松手吸附。
- 归位有四条路径：① 点锚点行的「召回 ←」；② 双击浮层；③ 拖回左栏（顶部投放区或边缘 56px 内）；④ 浮层聚焦时按 `Home`。归位后形态与位置都写回 `localStorage`，下次进来仍是栏内。
- 不做「灰色剪影占位」：空槽会持续提醒"这里本来有个东西"，比空着更难受。

**浮层的行为约定**

- 坐标：`transform: translate3d(x, y, 0)`，不写 `left/top`（避免逐帧 reflow）；`x/y` 存视口相对比例，窗口缩放后按比例还原并 clamp 到 8px 边距内。
- 拖拽：Pointer Events + `setPointerCapture`；起点位移 > 6px 才进入拖拽，否则算点击（沿用 dsh-whale-girl 的阈值）。
- 惯性：采样最近 120ms 的速度，> 800px/s 进入甩抛；每帧摩擦 0.985，< 34px/s 停止；撞边只在 > 120px/s 时反弹，低速直接停（避免贴边抖动）。
- 吸附：距左右/下边缘 < 56px 时贴边，只露 48px；hover 或聚焦展开。
- 落点：可落在对话区、依据台之上，但**不遮挡输入框**——输入框获得焦点或被 hover 时，浮层自动让位（平移到最近空白角）。
- 手势隔离：只有立绘本体启动拖拽；正文划词、课件拖入不受影响；浮层内的按钮（说话/收起/菜单）用 `stopPropagation`。
- 键盘：`tabIndex=0`，方向键每次 8px，`Home` 回左栏，`Esc` 停止拖拽。
- 持久化：`localStorage['notebuddy.pet.pos'] = {xRatio, yRatio, size, mode}`；「恢复默认位置」在右键菜单。
- 降级：`prefers-reduced-motion` 下关闭浮动/惯性，只保留拖拽；窄屏与打印不渲染浮层。

**本轮不再坚持「只做两档」**：原先判断浮层会压字、与 `.assistant-fab` 重复，这两个问题可以解——①浮层默认贴右下角并支持半隐藏；②把 `.assistant-fab` 与浮层合并成同一个实体（未展开时是桌宠，点击展开是抽屉）。

### 4.6 参考实现拆解：dsh-whale-girl（2026-10-20 调研）

仓库：<https://github.com/nickkkkkk123123/dsh-whale-girl>（MIT，v0.4.4）

**它是什么**：DSH（DeepSeek Harness）的「鲸鱼娘」挂件插件，显示余额/用量/上下文占用，支持拖拽、甩抛、重力、入睡、右键菜单。

**关键结论：它不是原生桌面窗口。** `src/client/index.tsx` 里创建一个 `position: fixed; z-index: 2147483647` 的宿主 `div` 挂到 `document.body`，再用 React `createPortal` / `createRoot` 渲染；README 明确写「额外进程 0 个 —— 挂件是 DSH Web UI 内的一个 DOM 节点」。所以它的「桌面挂件」= **应用内浮层**，和我们要做的 B 档是同一类东西，不涉及 Electron 透明置顶窗。

**挂载方式（可直接照搬）**

```ts
if (document.getElementById('dsh-whale-girl-mount')) return  // 防重入
const host = document.createElement('div')
host.id = 'dsh-whale-girl-mount'
host.style.cssText = 'position:fixed;z-index:2147483647;top:0;left:0;width:0;height:0'
document.body.appendChild(host)
// 有 slots 走宿主插槽，没有就直接 createRoot 挂 body
```

这段解决了三个我们也会遇到的问题：被侧栏/抽屉的层叠上下文盖住、路由切换重复挂载、宿主没有插槽时的降级。

**拖拽与物理（数值可参考）**

| 机制 | 数值 / 做法 | 我们是否采用 |
|---|---|---|
| 点击 vs 拖拽 | 位移 > **6px** 才算拖拽，否则触发点击台词 | 采用 |
| 指针 | Pointer Events + `setPointerCapture`，window 上监听 move/up | 采用 |
| 定位 | `transform: translate3d(x,y,0)`，不写 left/top | 采用 |
| 速度采样 | 最近 **120ms**、最多 10 个采样点、至少 3 点，松手估算 px/s | 采用 |
| 甩抛阈值 | **800px/s** 进入惯性；每帧摩擦 **0.985**；**34px/s** 停止 | 采用（可降到 600） |
| 撞边 | 仅入射 > **120px/s** 才反弹，低速归零贴边 | 采用（避免抖动） |
| 边缘吸附 | **120px** 判定范围 | 改为 56px（学习场景不需要大幅甩抛） |
| 重力 | 落地反弹、地面摩擦 0.95 | **不采用**：会把桌宠甩到证据台上 |
| 中键弹弓 / 拖尾 / 音效 | 弹射、蓝光点、合成音 | **不采用**：玩具属性，干扰阅读 |
| 省电 | 60s 无交互停动画；5–10min 入睡；hover 不算交互 | 采用（降到 30s / 关浏览器标签时停） |
| 状态 | 宿主经 `postMessage` 广播 `__wgWorkState`（thinking/done）→ 徽标 + 台词 | 采用（直接读 `conversation.busy` / `agentRun`） |
| 位置记忆 | **没有做**（只有「恢复默认位置」） | 我们补上，存相对比例 |
| 配置 | localStorage + POST 回宿主双写 | 我们只写 localStorage / 用户设置 |
| 资源 | 立绘量化到 46KB、data URL 内嵌（因宿主 403 子资源） | 不需要，我们用 webpack/vite 静态 webp 雪碧图 |

**它踩过、我们也会踩的坑**

- 流式输出卡顿：宿主每个 token 重渲染整条消息，挂件同主线程被拖累。他们的解法是「等上游按动画帧合并」+ 自己 `transform` 定位、物理循环减负。我们的启示：**拖拽坐标不要放进 React state 逐帧 setState**，用 ref + rAF 直接写 style；流式文本与物理循环互不阻塞。
- 层叠上下文：挂到 `shell.overlay` 会被固定定位容器盖住，最终挂 body 顶层。
- 双端挂载重复：官方 loader 双路径 apply，靠 mount id 防重入。

**与本项目的冲突清单（必须先处理）**

1. `.assistant-fab`（`styles.css:1862`）+ `AssistantDock` 已经是右下角的可移动 AI 入口；再加浮层会出现两个实体。建议合并：浮层未展开 = 桌宠本体，点击 = 展开抽屉。
2. 答疑页 `dockSupported = !isAssistantPage`（`AppLayout.tsx:121`）：浮层要跨页就得改这个开关，改成「浮层常驻，抽屉只在非答疑页可用」。
3. 拖拽手势与「划词追问」「拖课件进输入框」冲突：只在立绘本体启动拖拽。
4. 浮层压输入框：输入区聚焦时自动让位。
5. 移动端不浮层，收成顶部条。

**工作量**

| 范围 | 内容 | 估时 |
|---|---|---|
| 最小可用 | 浮层 + 拖动 + clamp + 位置记忆 + 双击回落 | 1 天 |
| 完整 | 惯性/吸附/半隐藏/让位/键盘/右键菜单/与 dock 合并 | 2–2.5 天 |
| 桌面级置顶（可选） | Electron 第二窗口：`transparent + frame:false + alwaysOnTop + setIgnoreMouseEvents`，IPC 同步会话状态 | 4–6 天，仅桌面版生效 |

## 七、取舍与风险

| 风险 | 处理 |
|---|---|
| 三栏挤压中栏，在 1280 笔记本上正文过窄 | 以 1440 为界；窄屏依据台改抽屉，不做永久三栏 |
| 角标精度依赖 `claims` 与句子对齐 | 当前 `claims` 只有 `claim_key + source_indexes`，无法定位到句时降级为「段落级角标」，并在文案上说明 |
| 桌宠动效干扰阅读 | 动效跟随 `prefers-reduced-motion`；提问期间不抢焦点、不弹气泡 |
| 会话删除是破坏性操作 | 服务端软删除 + 二次确认，与笔记/资料的回收站策略一致 |
| 范围收窄后答不出来 | 显式降级：「该页面没有相关内容」，并提供「放宽到整讲 / 整门课程」一键操作 |

**明确不做**：语音/3D 桌宠、多助手并排、在答疑页内嵌富文本编辑器、独立于课程资料的第二套知识库。
