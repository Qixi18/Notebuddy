## 7. 文档处理当前链路

上传原文件 → Asset 资源登记 → Worker 创建/执行 ParseRun → Native 或 MinerU → DocumentIR（页、块、章节、质量、来源）→ 笔记生成或检索答疑。

- 当前 .env 选择 MinerU standard，并开启 image analysis；示例/代码默认值不等于本机实际选择。
- Native 路径使用文本抽取、页面渲染和可选 OCR；PyMuPDF 不在基础环境时有 pypdfium2 渲染替代。
- 图片证据保留到 derived/figures，页面渲染保留到 derived/pages；来源接口给图片地址带上 run_id，以定位具体解析版本。
- 解析与正文生成分开：解析负责忠实提取来源，生成负责组织和解释内容。模型描述需要保留原图核对。
- 未配置 NOTEBOOK_VISION_* 时，不能宣称外部视觉 API 已接通；MinerU 自己的本地视觉推理仍可独立工作。
- 详细引擎说明：[document-processing-engines.md](<D:/工作台/Notebuddy软件开发/Notebuddy/docs/document-processing-engines.md>)。

## 9. 启动方式与端口

统一脚本：[dev.ps1](<D:/工作台/Notebuddy软件开发/Notebuddy/scripts/dev.ps1>)；Vite 配置：[vite.config.ts](<D:/工作台/Notebuddy软件开发/Notebuddy/apps/web/vite.config.ts>)。

- 脚本优先 `.venv-document/Scripts/python.exe`，缺失才回退 `.venv`。
- 脚本先执行数据库迁移，再启动 Worker 和 API，最后启动 Vite。运行它会进行迁移，并非纯查看操作。
- 当前脚本前端默认 5173，API 默认 8000；实际绑定使用 127.0.0.1。此前使用 localhost:3000 的要求不等于当前脚本已改成 3000。
- Vite `/api` 代理到 `http://127.0.0.1:8000`。
- 本轮监听快照未发现 3000、5173、8000 的监听项；未做 HTTP 请求，不能据此推断其他端口或其他电脑的部署状态。
- 独立 Worker 入口 `python -m app.workers.runner`；API 入口 `uvicorn app.main:app`。必须在 apps/backend 目录并选择正确 Python 环境。
- Windows 下 MinerU 渲染涉及 multiprocessing；stdin 诊断脚本曾失败，正式诊断应使用有 `if __name__ == "__main__":` 保护的脚本文件。
