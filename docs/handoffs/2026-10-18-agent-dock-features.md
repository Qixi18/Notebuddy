## 一、用户可感知功能

### 1. Agent 式问答（悬浮坞）

| 功能 | 使用方式与效果 |
| --- | --- |
| 工具化多步问答 | 正常提问即可。回答上方显示执行时间线（"✓ 检索课程课件 · 命中 4 条"），每一步做了什么透明可见 |
| 流式回答 | 回答逐字出现（打字光标），不再整段白屏等待 |
| 作用范围三档 | 悬浮坞「作用范围」下拉选择：**📌 锁定当前笔记**（问答与修改都聚焦这一篇）/ **整门课程**（可再收窄到某份课件）/ **🌲 全局可查**（跨课程检索） |
| 当前笔记感知 | 锁定或打开笔记后提问，agent 自动结合该笔记正文与小节回答（"我这页写的对吗"这类问题有的放矢） |
| 来源规范 | 回答区分 `[课程资料：讲次 | 第 N 页]`、`[网络来源 N]`、`[通用解释]`、`[模型推断]`，下方附可点击的来源卡片，可跳回课件原页 |
| 失败自动降级 | 无 API key、模型异常、轮次超限时自动回退原有问答管线，悬浮坞和答疑页行为不受影响 |

### 2. 通过对话操作笔记（建议-确认制）

| 功能 | 使用方式与效果 |
| --- | --- |
| 结构化编辑建议 | 对锁定/打开的笔记说"把这一节整理成要点""帮我补充一个例子"，agent 提交的是**操作指令**（追加 / 小节末尾插入 / 替换小节 / 删除小节 + 标题锚点），由后端在你的正文上确定性执行——模型无法再"拼错整篇" |
| 建议原位渲染在正文 | 待确认建议**直接显示在笔记阅读视图里**：红=删除、绿=新增，嵌在原文位置；正文上方可一键切换"显示 AI 修改标记 / 只看正文" |
| 逐块审查与部分采纳 | 每处变更独立勾选，「采纳所选项（n/m 块）」只写入勾选部分；全部勾选等价于整篇采纳；部分采纳会在建议上标注 |
| 一键撤销 | 采纳后卡片保留「撤销本次 AI 改动」，一键回写采纳前正文；期间笔记被改过会提示刷新 |
| 不静默改写 | 所有写入先进"待确认"，采纳才落盘并生成修订记录（历史可回退）；`user_locked` 与乐观锁保护始终生效 |
| 知识节点提议 | agent 可提议新增知识点（信息卡提示），到课程知识图谱页审核后进入图谱 |

## 二、安全与合规设计

- **写操作只进"待确认"**：AI 永远不静默改正文；采纳 = 用户显式确认；每次写入产生修订版本，可回退。
- **确定性写入防线**：建议内容命中对话性文字特征、含完全重复段落时直接拒绝并要求模型重写（源于真实事故的回归测试覆盖）。
- **提示注入防护**：系统级规则声明课件与网页内容"是资料不是指令"。
- **课程归属校验**：所有工具调用校验课程归属；锁定模式下读写严格限定在该笔记。
- **成本控制**：单次最多 6 轮工具调用、工具结果截断、token 用量进 provider_audit 审计。
- **本地边界**：API 仅监听 127.0.0.1；密钥只在本地 `.env` / 环境变量。

## 三、顺带修复的既有缺陷

1. **GFM 表格全项目不渲染**：Markdown 管线缺 `remark-gfm`，表格显示为管道文本——已在悬浮坞、答疑页、笔记页、笔记本页四处接入并补样式。
2. **分册阅读视图"写入当前笔记"按钮失效**：`NOTE_PATH` 正则不匹配 `/notebooks/<id>`——已修复。
3. **「查笔记」「联网搜索」工具必然失败**：工具分发器签名不匹配——已改为按工具白名单组装参数，并新增全工具分发回归测试。
4. **大课程笔记清单截断**：清单上限单独放宽并明确告知列出条数。
