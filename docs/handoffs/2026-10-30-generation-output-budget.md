# 笔记生成 JSON 输出预算与有界恢复

## 原因与边界

同步生成器曾用同一批原文和同一 `max_tokens=8000` 再生成整份 JSON，修复请求未改变造成截断的输入/输出预算。计划只计原文字符，忽略 Tiptap 节点和逐节点来源映射开销，较多短原文块同样容易生成长 JSON。当前 DeepSeek API 的 thinking 默认开启；生成预算还可能在产生正文前用尽。

官方文档（2026-10-30 核对）：

- [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)：thinking 默认、max_tokens 和 finish_reason=length。
- [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：JSON 模式仍需合理的输出预算，可能截断或返回空内容。

## 实现

- 只有结构化笔记生成请求显式使用 `thinking.type=disabled`；普通同步请求默认不传该选项，流式 Agent 的思考与工具调用契约保持原样。
- 单请求最多 20000 token，保留远端新增输出能力；生成、JSON 语法修复、来源修复与正文格式修复统一引用 `budget.py` 的 `NOTEBOOK_GENERATION_MAX_OUTPUT_TOKENS`。以正文膨胀及节点/来源开销估算目标仍为 6000 token，给实际输出留余量。该估算是保守启发式，不是提供商 tokenizer 保证。
- 新计划按字符与输出估算同时分批；composer 对历史持久化计划同样预先按原文块分批，不重写原始快照或计划。
- JSON 响应只要 `finish_reason=length` 就抛出可恢复截断错误，涵盖空内容与恰好可解析的 JSON。生成器按知识单元或原文块二分后重新生成，不拼接、补括号或接纳部分 JSON。
- 单原文块仍截断立即以 `model_output_limit` 清晰失败；每个原始 composer 批次最多 32 次 API 调用，包含语法/来源修复。网络连接错误维持可见失败与用户主动重试，不增加隐式网络重试。
- 全部子批通过严格来源校验才返回；任一子批失败，worker 继续保持正文/来源原子追加和任务重试幂等。
- 保留数学、callout、表格等本地格式归一化；首次正文格式校验失败时，整项任务最多额外执行一次非思考模式的模型格式修复。修复必须保留所有原正文块 ID 与各块的精确来源集合；持续截断或再次校验失败均拒绝追加，不产生无限重试。
- 各次模型输出可能复用 `p0` 等节点 ID。composer 和 worker 使用同一合并函数，在复制节点时同步重命名冲突 ID 及其精确来源，避免跨批来源混合。

## 验证与限制

相关自动测试使用合成原文、HTTP 边界模拟响应及独立 SQLite 数据库，覆盖空/损坏/可解析 JSON 截断、历史计划分批、单块失败、请求上限、子批来源隔离、模型 ID 冲突、用户正文保留、失败无部分落库以及重试仅追加一次。合并兼容回归另覆盖统一 20000 token 上限、非思考格式修复、禁止修改原 ID/证据、数学归一化先抛错后的自动修复以及格式修复失败保持原子性。

建议后续真实验收使用 1–2 页合成资料，创建新笔记后生成一次，核对正文与逐块来源，再确认用户编辑仍在、完成任务重复派送不重复追加。本次修复不自动重新提交真实 71 页资料，也不将真实正文或密钥写入回归样例。
