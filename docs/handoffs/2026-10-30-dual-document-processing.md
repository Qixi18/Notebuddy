# 双路线文档处理交付记录

日期：2026-10-30。分支：`feat/document-processing`，基点 `31e87d73ed35f01705ea675211ae785a98f760aa`。按用户指令提交并推送该分支；本地运行环境、用户资料和验证产物保留在本机。

## 已实现行为

- 设置 → 文档处理 → 默认文档处理路线：**标准处理 / 全程 AI**。保存为后端配置，默认标准处理；上传入口可单次覆盖。已上传和重试任务保留原路线与非敏感模型连接身份。
- 全程 AI 使用主 API 进行页面识别、跨页章节规划、笔记生成与藤蔓关系判断。PDFium 只渲染；Office 只转换为 PDF；不执行本地 OCR、文字层语义解析或 MinerU。正文、来源、知识树和关系继续使用现有数据契约。
- 新路线默认 200 MiB / 2,000 页，标准路线保持原限制，原始图片仍限 20 MiB。上传流式落盘；读取、规划、正文和关系均有持久成功检查点。
- 每轮读取两个新页后让出；旧页不重渲染、不重复逐页提交进度。不同课程轮转，同一本笔记的生成任务仍按原顺序串行。每个正文批次使用独立 ID 命名空间，并同步来源映射。
- 已失败的原件可改用 AI；同批混合路线分别建生成任务。可取消读取、重试生成或独立重试藤蔓分析。切换设置不自动重复追加已生成正文。
- AI 关系分析遍历全部当前跨课小节的分批内容，移除标准路线 24 个候选的截断。用户删除的关系有持久抑制记录，人工关系不会被自动覆盖。
- Office 转换有超时、专用输出目录及进程身份记录。仅清理本任务新建且 PID/启动时间均匹配的 Word/PowerPoint 进程，不操作用户已有实例。
- 修复了浏览器实测中桌宠按钮盖住设置保存按钮的问题，以及基线已存在的“AI 完成时未显示本地未保存草稿提示”问题。

## 实施决定和代价

1. 继续在用户已指定的本地 feature 分支执行，保留原有 `.runtime/`、`apps/web/output/`；没有另建工作树。代价是必须严格使用隔离测试数据。
2. 设置作为新上传的服务端默认值，显式单次选择优先；旧持久记录仍为标准路线。旧客户端会跟随用户新设置，而非永远强制标准路线。
3. 本机执行并保留 Windows 进度记录，完成验证后按用户指令提交并推送当前分支。测试日志与合成文件留在本任务 git-ignored `.superpowers/sdd/2026-10-30-dual-document-processing/`，供追溯。
4. 检查点仅保存已验证的成功结果，失败状态和尝试身份保留在任务表中。服务商可能已对失败请求计费；不承诺重试绝对不重复收费。
5. 每次仅一页视觉调用，每完成两个新页让出，限制在设计的最多两路并发以内。代价是吞吐低于并发两路，换取与现有串行执行器的稳定衔接。
6. 保留现有文件库、正式正文及来源表；派生树仍来自模型生成的标题。未建立第二套业务数据源。
