# 培养方案导入完善

用户要求基于现有结构完善培养方案导入，承接已确认的缺口：重试不轮询、未接全程 AI、长文档无步骤恢复、课程字段有限、缺少方案对比与撤销。以下实现细节由执行者按现有结构选择。

## 设计

沿用 `CurriculumImport` → `ForestJob` → 可编辑预览 → 确认建课/关联的流程。新上传默认使用设置中的 `standard` / `llm` 路线，也可单次指定；路线与非敏感模型身份写入现有 ForestJob 的 JSON 快照，重试保持原路线。旧记录默认标准路线。

标准路线保留本地 PDF/DOCX/文本解析；已配置模型时分批提取，无模型时明确显示本地规则。全程 AI 文件路线复用现有页渲染、模型读页和结构化调用；粘贴文本直接分批交给模型。成功页与提取批次复用 `ProcessingStep`，指纹包含源内容、路线、模型身份与提示版本。分次让出 Worker，失败不清除成功步骤。

课程行增加课程代码、学分、学时、必修/选修信息，保存在现有 `rows_json`。森林仍只从现有 profile 获取学期、层级与先修属性；课程附加字段属于培养方案记录，不创造 Notebook 或正文来源。

预览提供筛选/恢复课程行、重复/无效字段提示、学分汇总、已有课程的属性变更提示，以及与最近已确认导入的语义对比。来源位置和原文不可修改。确认事务保留每个课程的映射、修改前后 profile 与版本，以支持安全撤销。

撤销只作用于该次确认：课程属性必须保持确认后的 revision；新建课程必须仍为空、未被改名或写入描述、没有 Notebook/历史 Note/会话等使用痕迹。通过后先按现有备份规则创建检查点，再恢复旧属性、将新建空课程送到回收站；任何冲突整批拒绝，保留正文和用户后续修改。旧导入无快照时不给撤销入口。

## 结构选择

采用现有 JSON 与步骤表扩展。相比新增一套培养方案任务/文档系统，这样保留统一 Worker 和模型缓存；相比给用户真实库新增迁移，现有字段已经足够保存本轮导入元数据和确认快照，无需数据库结构变更。页面读图的公共函数与普通文档共用，输出契约保持不变。

## 验收重点

- 重试返回 pending，前端继续轮询；重复确认/重试不能制造重复课程或作业。
- 路线默认/覆盖/重试冻结、无模型错误、扫描 PDF、DOCX 转页失败及页数上限。
- 第 N 步失败重试只调用缺失步骤；坏来源、伪造先修与截断输出不能进入预览。
- 新字段校验、空白/同名/代码冲突、关联既有课程、用户 profile revision 冲突及事务回滚。
- 方案对比不删除课程；撤销遇到后续内容/改名/版本变化必须拒绝。
- 隔离库和合成输入验证，禁用付费服务；完整官方检查与浏览器 QA。
