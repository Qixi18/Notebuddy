# 方案 A：课程笔记本与讲次章节设计

日期：2026-10-08
状态：用户已选择方案 A；本文件为待评审技术设计，尚未开始业务代码实现。
需求依据：[NoteBuddy需求说明](../../../NoteBuddy需求说明.md)；用户本次确认：每门课一本笔记本，每讲一个章节，章节内按小节或知识点组织，知识树叶子跳到对应位置。

## 1. 目标与本轮范围

用户能从课程笔记书架打开一本课程笔记，按教学讲次与课件内容顺序连续阅读；也能从知识树的一片叶子进入该讲对应小节。相同知识点在不同讲次出现时，正文与叶子分别保留，关系负责表达相同、相关或深化。

本轮交付：
- 课程笔记书架、讲次目录、章节阅读、整本顺序阅读、小节编辑与来源/版本查看。
- 每讲独立笔记小节、跨讲知识关系与准确叶子跳转。
- 旧数据迁移、旧链接兼容、用户修改保护、课程隔离与备份恢复回归。

AI 选页补生成、难点筛选解释、桌宠交互与问答上下文、知识树完整艺术设计仍为后续任务。本轮提供其可用的数据与定位基础，不将这些后续能力计作本轮完成。

采用的业务默认：
- 一份上传资料代表一讲；资料的讲次标题作为章节标题。同名标题或重复文件作为新讲次导入时，仍有独立章节 ID，不按名称合并。
- 章节默认按导入先后排列，允许用户上移/下移调整教学顺序；不根据文件名或模型输出猜测讲次编号。
- 本轮沿用当前解析器的主要知识点粒度生成小节，并按资料内位置排序。小节是笔记阅读单位，PPT 页码只是来源位置，不作为笔记本页码。
- 多份文件合成同一讲、人工创建无来源章节、复杂拖拽排版不在本轮范围内。

## 2. 现状与结构选择

当前 `Note.knowledge_node_id` 唯一，`KnowledgeNode.note` 为单条关系；`ensure_note` 按知识节点找正文。不同讲次命中同一节点后，会共享笔记，并产生修改建议。前端知识树通过 `notes.find(knowledge_node_id)` 找入口，无法区分同一概念在哪一讲的具体小节。

两种技术选择：
1. 新建 Notebook、Chapter、Section 全套表，独立复制当前正文与版本机制：概念清晰，但迁移、备份及兼容成本较高。
2. 推荐：课程作为笔记本，资料作为章节，扩展现有 Note 为小节，继续使用现有修订与来源机制。

采用第 2 种。一门课恰有一本笔记本，不额外存一份重复正文；整本视图由有序章节和小节组装。知识节点表达课程概念，Note 表达概念在某讲的笔记正文，两者从一对一改为一对多。

```text
Course（一本笔记本）
 ├─ Material A（第 1 讲章节）
 │   ├─ Note A1（小节，关联知识点 X）
 │   └─ Note A2（小节，关联知识点 Y）
 ├─ Material B（第 2 讲章节）
 │   └─ Note B1（小节，关联知识点 X；正文独立）
 └─ KnowledgeNode X ↔ KnowledgeNode Y（概念关系）

Note A1 与 Note B1 共享概念 X，不共享正文、修订或叶子 ID。
```

## 3. 数据模型与约束

### 3.1 章节与顺序

`Material` 增加持久化 `chapter_order`，同课程按此字段排序；相同排序值以创建时间、ID 稳定打破平局。上传事务在课程范围内分配新位置。资料 API 增量返回此字段，既有字段保留。

`Course` 增加 `notebook_order_revision`，仅用于目录排序的乐观并发控制。上传、排序、资料移除与恢复会更新目录版本；它不替代 Note 的正文版本号。

重排请求必须覆盖课程内所有未删除资料，ID 不重复、不跨课，携带期望目录版本。版本冲突返回 409，前端保留当前阅读位置并刷新目录，不静默覆盖另一操作的排序。

### 3.2 笔记小节

`Note` 增加：
- `material_id`：所属讲次，外键指向 Material；迁移时允许 NULL 以保留历史整理。新解析生成的笔记必须属于真实且同课程的资料。
- `section_key`：资料内稳定生成位置键；初版以 ParsedPage 稳定位置键为基础，并预留同位置多个小节的序号。模型标题改名不改变此键。
- `section_order`：资料内排序，使用解析的文档顺序；相同值以 section_key、ID 稳定排序。

取消 `knowledge_node_id` 的全局唯一约束，改为 `KnowledgeNode.notes`。同资料的非空 section_key 唯一，保证重试/重解析不会制造重复小节；NULL 的历史条目不受该生成唯一键限制。

保留 Note ID、正文、content_origin、user_locked、revision_number、全部 NoteRevision、NoteSuggestion 与来源关联。知识关系确认不得删除或合并不同讲次的 Note。

`material_id` 的数据库删除策略使用 SET NULL，不让硬删除资料直接带走用户笔记；业务删除仍沿用软删除、检查点和活动任务保护。已移除资料的笔记在“已移除资料”目录组可查看，资料恢复后回到原章节；删除整个课程仍遵守现有恢复边界。

### 3.3 知识树叶子

概念节点和 KnowledgeEdge 保持课程级身份。新增图接口的 `occurrences` 字段，按 Note 记录每讲叶子：
`{ id: note_id, note_id, knowledge_node_id, material_id, section_key, section_order, title }`。

- 叶子唯一身份使用 Note ID，不能使用概念名称或 KnowledgeNode ID。
- 同概念的跨讲叶子以“同一知识点”关系关联，这是 Note 之间的派生关系，不写成 KnowledgeEdge 自环。
- 相关、先修、深化关系仍来自课程概念图；叶子详情列出对应讲次的目标小节，避免将全部叶子两两连线造成无意义的密集图。
- 选择叶子跳到确切 Note，不再按概念找第一篇笔记。
- 不自动用名字相似来改正文归属；相似候选先形成提案。整合确认只更新关系或概念关联，保留两讲的正文及入口。

## 4. 解析与编辑流程

处理顺序：
1. 解析资料并保存活动页面、块和来源。
2. 依据本资料 section_key 定位已有 Note，先决定本讲小节身份。
3. 精确同名知识点可复用课程概念节点，但为新讲次建立独立 Note。
4. 相似但不同名的知识点先保存本讲节点与 Note，再生成与历史节点的关联/深化提案；不能因等待确认而让本讲内容不可阅读。
5. 新小节创建正文及初始修订；已有小节重新生成时保存建议，正文不自动覆盖。
6. 全部节点就位后统一建立关系，维持现有两遍处理与跨课/循环校验。
7. 成功提交后刷新笔记本目录、图与来源覆盖。

重解析保留稳定 Note ID。找不到原位置或生成边界变化时，原小节保留并标记来源待核对；新增小节另建 ID，不把旧链接改指另一段内容。

小节保存继续发送 expected_revision_number，产生 NoteRevision 并锁定用户版本。409 时保留草稿；章节、叶子、前后小节与路由切换均执行未保存修改检查。

来源和网络补充按小节显示。网络来源查询不能因共享知识节点而混入另一讲资料的来源；应按 material_id 与既有来源证据共同筛选，历史整理明确展示其实际来源范围。

## 5. 接口与前端阅读

新增接口，均在现有 `/api/v1` 下：
- `GET /courses/{course_id}/notebook`：课程标题、目录版本、有序章节、每节元数据、处理中/失败/空章状态、历史整理和已移除资料分组。
- `GET /courses/{course_id}/notebook/chapters/{material_id}`：该讲按位置排序的小节正文与版本信息；严格校验课程归属。
- `PATCH /courses/{course_id}/notebook/order`：完整的章节 ID 顺序及 expected_order_revision。

现有 `GET /courses/{id}/notes`、`GET/PATCH /notes/{id}`、来源、修订、建议与反馈接口保留；NoteRead 增量提供章节和排序字段。调整 `schemas/api.py`、前端 types 和 api 模块的兼容导出。

阅读路径：
- `/notes` 改为每门课一本笔记的书架，显示章节数、已生成小节数和最近更新。
- `/courses/{courseId}/notebook` 打开课程笔记本，侧边目录列出讲次和小节。
- 使用查询参数 `chapter=<materialId>&section=<noteId>` 定位；小节 DOM 锚点由 Note ID 生成，不依赖标题。
- 章节模式显示当前讲全部小节；整本模式依目录顺序按章加载和拼接，保留章节边界。前后导航跨章工作，空章不伪造内容。
- 编辑仍以单个小节为单位，整本视图不维护另一份汇总正文。
- 原 `/courses/{courseId}/notes/{noteId}` 链接通过 Note 元数据跳转到笔记本定位；material_id 为 NULL 时进入历史整理。课件覆盖的 note_ids 也使用同一定位函数。
- 找不到、跨课程、已移除、生成中和来源失效情况显示明确状态，不悄悄跳到另一篇内容。
- 本轮沿用现有视觉风格，只完善笔记本层级、目录与阅读布局，不宣称知识树艺术设计已验收。

## 6. 旧数据迁移与恢复

新增 Alembic 修订，接在当前 `f7b9c2d6e401` 后；不修改已发布修订。沿用迁移前检查点。

- 资料按原创建顺序回填 chapter_order。
- 单篇旧笔记的所有实际来源只属于一份资料时，关联到该讲；按最早来源位置排列，迁移使用独立的 `legacy:<note_id>` 键，保留原 ID 和正文。
- 旧笔记没有来源，或来源跨多讲时，material_id 保持 NULL，显示在“历史整理”，并说明其来源范围。不得猜测拆分、复制用户内容并声称为各讲原文，或在迁移时调用模型改写。
- 多讲共享旧笔记后续重解析时，各讲新建自己的小节；历史笔记与修订继续可访问，未经确认不删除。历史来源继续参与真实覆盖，不能为制造“新增覆盖率”而移除已有引用。
- SQLite 重建唯一约束时保全被 notes 外键引用的修订、来源映射、建议、反馈与关联数据。执行 FK 检查、SQLite 完整性检查及迁移前后数量/内容校验。
- 同步核对 `db/migrate.py` 的无版本旧库兼容桥，不能让当前 ORM 元数据在 Alembic 之前提前添加约束或伪造升级状态。
- 备份快照包含新字段；课程范围包仍保持课程隔离。恢复旧包后正常升级，恢复新包后顺序、定位和用户版本不变。
- downgrade 若遇到同知识点多个 Note，明确拒绝有损降级并提示使用迁移前检查点；不得删笔记以强行恢复旧唯一约束。

## 7. 错误与数据保护

保持当前上传队列、任务重试、软删除、本地监听和密钥约束。
- 并发上传/重复任务不能分配重复小节或丢目录条目。
- 目录排序与正文保存分别有版本检查；失败不影响已保存正文。
- 生成失败仍显示对应章节和可重试状态，不删除已经生成的小节。
- 覆盖继续依据有效笔记来源事实，不能按章节存在或概念命中计入。
- 本轮不写入模型密钥，不迁移用户真实库做实验，回归使用隔离目录与生成资料。

## 8. 验收标准

自动回归至少覆盖：
1. 两讲包含同名知识点，生成两个不同 Note/叶子；修改第 1 讲不改变第 2 讲。
2. 目录按教学顺序、小节按资料位置排序；章节重排刷新后不变，旧目录版本写入返回 409。
3. 精确叶子、旧链接、覆盖入口定位同一个 Note；跨课程 ID 被拒绝。
4. 相似知识点待确认时本讲小节仍可阅读，确认或拒绝不会丢正文。
5. 重试与重解析不产生重复小节，旧链接、用户版本与待核对来源保持可追溯。
6. 旧库单讲、多讲、无来源、用户锁定等笔记迁移不丢 ID/正文/修订/来源；重复启动安全。
7. 资料软删除、恢复、课程备份及恢复后，目录、叶子、版本和覆盖事实正确。
8. 前后小节、章节和整本模式切换不会静默丢弃草稿。

浏览器验收：
- 书架进入课程 → 目录进入第 1 讲 → 整本顺序读到下一讲 → 编辑保存 → 刷新确认。
- 从第 2 讲同名知识点叶子进入第 2 讲正文，而不是第 1 讲。
- 新上传第 3 讲，前两讲正文和叶子入口保持；真实来源回跳到正确材料位置。
- 空课程、处理中章节、失败章节、历史整理、窄窗口、键盘目录导航和未保存提示有明确状态。

验证入口遵循 AGENTS.md：后端 Ruff/pytest、Web 构建、相关浏览器流程、隔离旧库与备份恢复回归。逐条检查命令退出状态；测试通过与真实 AI/课件质量验收分开记录。
