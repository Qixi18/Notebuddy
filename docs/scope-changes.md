# 范围变更记录

## 2026-10-11：知识森林新增范围

用户确认新增完整培养方案、跨课程森林和笔记叶子藤蔓。最终风格为自然手绘，替代早期夜间发光讨论；森林包含全部课程，正常桌面视口呈现 2–3 棵。培养方案先预览再确认，课程状态由用户控制；AI 候选关联在资料生成笔记后自动提出，经用户确认才成为藤蔓。具体决定见 [知识森林设计](superpowers/specs/2026-10-11-knowledge-forest-design.md)。

本次不合并跨讲正文，不放宽旧知识边和答疑的课程隔离。系统桌面挂件、测验等范围不随森林自动扩展。

## 答疑形态口径补充

下方 F-13 是历史页面式方案记录。最新用户需求仍要求应用内默认收起、点击展开侧栏的桌宠，并结合当前笔记和连续上下文；这些缺口不能因页面式教师已经存在而标记完成。本轮知识森林未将其列入实现，不修改其验收状态。

## F-13：精灵教师交互形态

- **原需求描述**：应用内悬浮桌宠、侧栏并排交互。
- **当前确认方案**：Windows 浏览器优先的本地 Web。精灵教师在首页和答疑页以内嵌页面组件显示，依据加载、思考、讲解和错误状态切换素材；不常驻系统桌面，不实现 Electron 桌面挂件交付。
- **影响范围**：阶段三、四的答疑和浏览器验收按页面式教师执行；`apps/desktop` 只保留安全包装骨架，桌面宠物和后端托管另立发布计划。
- **验收口径**：不把页面式教师与悬浮桌宠同时标记为完成。若后续恢复桌面挂件需求，需要新增范围、安装包、进程托管和桌面交互验收。

该记录与四阶段详细规划中的产品边界一致，用于在正式需求文档尚未修订时避免把两种交互形态混作同一项完成证据。
